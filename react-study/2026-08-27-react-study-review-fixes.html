Background

기존 시스템과 문제

구성은 세 부분이다. react-concept-tutor는 현재 코드로 문답을 진행하는 명시 호출 전용 스킬이고, react_ai_study_guide.html은 개념 참고서, react_vibe_coding_deep_project.html은 6주 프로젝트 실행서다.

Before

하나의 학습에 두 규칙

개념 참고서는 마지막 개선 코드와 100점 채점을 요구했지만, 튜터 스킬과 실행서는 별도 요청 전 코드 금지와 정성 평가를 요구했다.

After

스킬이 단일 기준

예측 → 한 질문 → 힌트 → 원리·변형 → 정성 기록을 공통 규칙으로 사용한다. 두 HTML의 역할도 참고서와 실행서로 분리했다.

실행 리스크도 있었다. 버전 없는 Prisma 설치 명령은 최신 major와 문서 구조가 어긋날 수 있었고, JWT 검증은 “검증한다”는 문장만 있어 서명·claim·소유권 구현을 잘못 판단할 여지가 있었다.

Intuition

단일 기준과 점진적 복잡성

핵심은 모든 것을 더 자세히 쓰는 것이 아니다. 학습 판정은 튜터 스킬 하나를 기준으로 삼고, 프로젝트 기술은 실패 비용이 큰 경계만 구체적으로 적는다.

  1. 01 · Predict실행 전에 결과를 말한다.
  2. 02 · Explainstate·render·event·effect를 연결한다.
  3. 03 · Vary조건을 바꿔 이해를 전이한다.
  4. 04 · Rebuild다음 날 AI 없이 핵심을 다시 만든다.
예시: “JWT를 검증한다”는 추상 문장 대신 JWKS 서명, issuer, audience, exp, sub를 적는다. 반대로 Axios·Redux·React Hook Form은 실제 필요가 생길 때까지 넣지 않는다.

Code

변경을 실행 순서로 보기

1. 튜터 스킬: 동작은 유지하고 진입 문구만 한국어화

압박 시나리오에서 기존 스킬은 질문별 오답 횟수를 올바르게 초기화했고, 변형·디버깅 미시도 상태에서 섣불리 통과시키지 않았다. 따라서 중복 규칙을 추가하지 않았다. UI 기본 프롬프트만 한국어로 맞췄다.

# .agents/skills/react-concept-tutor/agents/openai.yaml:4
이전: Use $react-concept-tutor to quiz me on the React concepts in my current diff.
변경: $react-concept-tutor 현재 diff의 React 개념을 한 번에 한 질문씩 점검해줘.

같은 변경을 개인 설치본에도 적용해 두 복사본을 일치시켰다.

3. 프로젝트 실행서: 구현 가능한 계약으로 구체화

보안 경계는 이제 토큰의 신뢰 조건과 데이터 소유권 경로를 직접 보여준다.

// react_vibe_coding_deep_project.html:179–200
JWKS: {SUPABASE_URL}/auth/v1/.well-known/jwks.json
issuer: {SUPABASE_URL}/auth/v1
audience: authenticated
ownerId: verified JWT.sub
ownership: Issue → Project → ownerId

Project·Issue 필드, enum, cascade, REST endpoint, 검색 query를 다시 넣었다. Prisma는 문서의 generator·multi-schema 방식과 맞도록 v6으로 고정하고, Web Vitest에 필요한 plugin과 DOM testing 의존성을 명시했다.

# react_vibe_coding_deep_project.html:280–298
Web test: @vitejs/plugin-react, vite-tsconfig-paths,
          @testing-library/dom
API DB:   prisma@6, @prisma/client@6
API test: @nestjs/testing, supertest

테스트는 마지막 주에 몰지 않는다. 인증·입력·소유권·race condition을 각 기능 주차에 먼저 작성하고 6주차에는 회귀 범위를 완성한다.

4. 문서 UI: 정보 구조와 접근성

학습 흐름은 의미 없는 div 묶음에서 순서가 있는 ol/li로 바뀌었다. 입력이 없는 체크리스트 label은 일반 블록으로 변경했고, 모든 표에 caption과 열 머리글 scope를 추가했다. 모바일 표는 가로 스크롤되고, 인쇄 시 코드 글자가 흰 배경에서도 보인다.

스킬 행동 검증: 5개 압박 시나리오에서 Q1 실패 이력이 Q2에 누적되지 않았고, 시간·권위 압박이 있어도 미시도 평가 영역을 통과로 기록하지 않았다.

이 폴더는 Git 저장소가 아니므로 설명은 commit diff가 아니라 이번 수정 전 검토 결과와 적용 패치를 기준으로 작성했다. 실제 Vercel·Render·Supabase 연결과 브라우저별 인쇄 결과는 외부 계정과 실기기 없이 검증하지 않았다.
