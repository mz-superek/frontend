연습 서비스: 개인용 이슈 관리

최소 아키텍처

apps/
  web/   # Next.js App Router + TypeScript
  api/   # NestJS REST API + Prisma

DB/Auth  # Supabase PostgreSQL + Auth

공통 패키지는 처음부터 만들지 않는다. 실제 타입 중복이나 계약 불일치가 생긴 뒤에만 추가한다.

인증·데이터 흐름

  1. Next.js에서 Supabase Auth로 로그인한다.
  2. access token을 Bearer token으로 NestJS에 전달한다.
  3. NestJS가 token을 검증하고 사용자 ID를 추출한다.
  4. NestJS만 PostgreSQL에 접근한다.
  5. 모든 쿼리에 인증 사용자 소유권 조건을 둔다.
보안 경계: ownerId는 요청에서 받지 않는다. NestJS는 Supabase JWKS로 JWT 서명과 issuer·audience·exp를 검증하고, 검증된 sub만 사용자 ID로 사용한다. 앱 테이블은 Data API에 노출하지 않는 app 스키마에 두며 DB URL과 secret/service role key를 브라우저에 노출하지 않는다.

검증 기준 예: JWKS {SUPABASE_URL}/auth/v1/.well-known/jwks.json, issuer {SUPABASE_URL}/auth/v1, audience authenticated. JWT payload를 단순 decode한 결과는 인증 근거로 사용하지 않는다.

기본안은 Client Component에서 세션을 확인하고 화면을 이동시키는 구조다. 이 redirect는 UX 경계일 뿐이며 실제 보안은 NestJS API가 담당한다. Server Component·Middleware에서 세션을 읽어야 할 요구가 생길 때만 @supabase/ssr를 추가한다.

Web은 Vercel Hobby, API는 Render Free, DB/Auth는 Supabase Free를 사용한다. Render처럼 지속 실행되는 API는 Supabase의 session pooler 연결 문자열을 사용하고 포트는 5432로 둔다. 무료 플랜의 cold start와 비활성 중지는 학습용 데모의 제약으로 허용한다.

React 튜터 서브에이전트 스킬 설계

개인 스킬 react-concept-tutor는 자동 실행하지 않고, 학습자가 명시적으로 호출할 때만 시작한다.

튜터 진행 규칙

  1. 현재 diff·관련 파일·기능 목표를 확인한다.
  2. 분석 서브에이전트가 핵심 개념, 예상 오개념, 질문 3~5개, 답변 기준과 반례를 준비한다.
  3. 현재 에이전트는 질문을 한 번에 하나만 제시한다.
  4. 첫 오답에는 정답 대신 힌트만 제공한다.
  5. 두 번째 오답에는 원리를 설명하고 조건을 바꾼 문제를 제시한다.
  6. 별도 요청 전까지 완성 코드나 수정 코드를 제공하지 않는다.
  7. 서브에이전트를 사용할 수 없으면 현재 에이전트가 같은 규칙으로 진행한다.

통과에 필요한 행동

  • 실행 결과를 사전에 예측한다.
  • state·render·event·effect 관계를 자기 말로 설명한다.
  • 조건이 바뀌었을 때 결과를 설명한다.
  • 잘못된 코드의 원인을 찾는다.
  • AI 없이 재구현할 부분을 식별한다.

피해야 할 튜터 행동

  • 첫 질문과 함께 답을 알려준다.
  • 용어 암기만 확인한다.
  • 코드와 무관한 일반 문제만 낸다.
  • 숫자 점수로 이해 여부를 뭉뚱그린다.
  • 학습자 대신 코드를 수정한다.

개념을 이해하는 가장 짧은 방법

  1. 예측: 코드를 실행하기 전에 화면과 로그 순서를 적는다.
  2. 추적: 어떤 이벤트가 어떤 state를 바꾸고, 어떤 렌더를 만드는지 말한다.
  3. 반례: dependency 제거, derived state 중복 저장, 느린 응답 등 잘못된 버전을 직접 재현한다.
  4. 교정: 공식 문서와 실제 실행 결과를 AI 설명과 비교한다.
  5. 전이: 조건을 바꾼 문제를 풀고 다음 날 핵심 부분을 AI 없이 다시 만든다.

작은 PR의 병합 조건

□ 생성된 코드를 학습자가 설명한다.
□ 테스트가 구현 전 실패하고 구현 후 통과한다.
□ 불필요한 state와 Effect가 없다.
□ 로딩·오류·빈 상태를 처리한다.
□ 키보드·label·role·name 기본을 지킨다.
□ 다른 사용자 데이터에 접근할 수 없다.
□ 튜터의 설명·예측·변형·디버깅을 통과한다.
□ 다음 날 핵심 부분을 AI 없이 재구현한다.

Web 회귀 기준

  • 인증 상태에 따른 화면 접근
  • 프로젝트·이슈 CRUD와 폼 검증
  • 검색·필터 조합과 오래된 응답 처리
  • 로딩·오류·빈 결과
  • 키보드·focus·접근 가능한 label·role·name

API 회귀 기준

  • 미인증 401, 잘못된 입력 400, 없는 리소스 404
  • 다른 사용자 리소스 조회·수정·삭제 차단
  • 프로젝트 삭제 시 Issue cascade
  • 제목·상태·우선순위 필터 결과
  • 검증된 JWT sub 기반 소유권

6주 뒤 최종 과제

  1. 핵심 화면의 상태와 데이터 흐름을 그림 없이 설명한다.
  2. 불필요한 state와 Effect를 찾아 제거한다.
  3. 버그 하나를 테스트로 먼저 재현하고 수정한다.
  4. 핵심 기능 하나를 AI 없이 다시 구현한다.
  5. 튜터 세션에서 설명·예측·변형·디버깅을 통과한다.

최종 성공 기준: 공개 URL에서 로그인부터 이슈 관리까지 동작하고, 데이터 소유권·테스트·빌드를 검증하며, 학습자가 핵심 React 개념을 자신의 말과 코드로 재현한다.
