# 코테 연습장 — AI 코드 검증

AI가 뱉은, 언뜻 멀쩡해 보이는 코드를 받아서 **검증하고 설명하는** 연습장.
"빨리 짜기"가 아니라 "요구사항에 대보고 → 결함을 실행으로 재현하고 → 왜 그런지 설명하고 → 고치고 → 진짜 고쳐졌는지 다시 검증하기"가 목적이다.

## 실행

```bash
cd practice
npm install
npm run dev        # http://localhost:5180 (브라우저 자동 실행)
```

타입 검사만 따로 돌리려면:

```bash
npm run typecheck
```

## 폴더 구조

```text
practice/
├── src/
│   ├── main.tsx                     QueryClientProvider + Devtools 세팅
│   ├── App.tsx                      문제 선택 탭 + 에러 경계
│   ├── mock/api.ts                  가짜 서버 (고치지 않는다)
│   └── problems/
│       └── 01-team-members/
│           ├── SPEC.md              👈 문제 설명 + 검증 기준
│           └── TeamMemberList.tsx   👈 검증 대상 코드
```

문제를 풀 때는 **`SPEC.md`를 먼저 읽고**, 그 스펙을 `TeamMemberList.tsx`에 하나씩 대본다.

## 규칙

1. `mock/api.ts`는 서버다. **고치지 않는다.** (스펙이 아니라 구현을 바꿔 통과하는 건 반칙)
2. 결함은 **읽어서 짐작한 것으로 끝내지 않고, 실행해서 재현**한다. 재현 방법까지 말할 수 있어야 진짜 찾은 것이다.
3. 고칠 때는 **한 번에 하나만.** 고친 뒤 그 하나가 됐는지 확인하고 다음으로 넘어간다.
   (여러 군데를 동시에 고치면, 잘 돌던 걸 실수로 깨뜨렸을 때 알아채기 어렵다.)
4. 해설은 먼저 보지 않는다. 리뷰를 먼저 남기고, 그다음 채점받는다.

## 검증 도구

| 도구 | 용도 |
| --- | --- |
| 브라우저 콘솔 | `[api #n]` 로그 — 요청이 몇 번, 어떤 파라미터로 갔는지 |
| React Query Devtools (우하단) | 캐시에 어떤 `queryKey`가 있고 안에 뭐가 들었는지 |
| 새로고침 | 화면 값이 *서버의 진실*인지 확인 |
| `npm run typecheck` | 타입 레벨 결함 |
