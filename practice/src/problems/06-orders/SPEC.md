# 문제 06 — 주문 관리 테이블 (필터·정렬·선택·페이지)

## 상황

관리자용 주문 테이블을 AI에게 시켰다.
받은 결과가 [OrderTable.tsx](./OrderTable.tsx)다.

**나는 이 코드를 짠 사람이 아니라 리뷰어다.**
프로덕션에 올려도 되는지 판단하고, 문제가 있으면 *무엇이 / 왜 / 어떻게 고칠지* 설명한다.

버그가 몇 개인지, 있는지 없는지는 알려주지 않는다.

> 지금까지는 결함이 **한 기능 안에** 있었다. 06번은 다르다.
> 필터·정렬·선택·페이지 — 넷 다 따로 보면 멀쩡하다.
> **문제는 이것들이 서로 부딪히는 지점**에서 생긴다.
> "필터를 바꿨을 때 페이지는 어떻게 되지?", "페이지를 넘겼을 때 선택은?"
> 조합을 하나씩 밟아봐야 보인다.
>
> 그리고 이 화면에는 **되돌릴 수 없는 작업**(일괄 완료 처리)이 있다.
> 그런 화면의 결함은 사고로 이어진다.

## 제품 스펙 (이걸 검증 기준으로 쓴다)

1. **필터** — 상태를 고르면 그 상태의 주문만 보인다. 건수 표시도 맞아야 한다.
2. **정렬** — 정렬 기준을 바꾸면 그 순서로 보인다.
   **`기본순`으로 되돌리면 원래 순서(o1, o2, o3 …)로 돌아와야 한다.**
3. **페이지** — 5건씩 나눠 보여준다. 페이지 버튼은 **지금 목록에 실제로 있는 만큼만** 나온다.
   필터를 바꿔서 건수가 줄면 페이지 수도 줄어야 하고, **빈 페이지가 보이면 안 된다.**
4. **선택** — 체크한 주문만 선택된다. `N건 선택됨` 표시는 **실제 선택과 항상 일치**해야 한다.
5. **일괄 처리** — `선택한 주문 완료 처리`는 **사용자가 화면에서 보고 고른 것만** 처리한다.
   **화면에 보이지도 않는 주문이 처리되면 절대 안 된다.**
6. **안정성** — 어떤 조작을 어떤 순서로 하든 렌더링이 깨지면(크래시) 안 된다.

## 검증 도구

- **`N건 선택됨` 표시** — 화면의 체크박스와 이 숫자를 대본다. 스펙 4번.
- **콘솔 `[bulk]` 로그** — 일괄 처리할 때 **어떤 id가 실제로 처리됐는지** 그대로 찍힌다.
  스펙 5번은 이 로그 말고 확인할 방법이 없다. **화면에서 체크한 것과 로그가 같은지** 대본다.
- **`기본순`의 원래 순서** — 처음 화면을 열었을 때 순서가 `김민수 → 이서연 → 박지훈 …` 이다.
  이 순서를 기억해두고, 정렬을 이리저리 바꾼 뒤 `기본순`으로 돌아와서 비교한다.
- **페이지 버튼 개수** — 필터를 바꿨을 때 버튼 개수가 따라 줄어드는지 본다.
- **`↻ 처음부터 다시` 버튼** — 상태를 초기화한다.
  (다만 이 문제의 결함 중 하나는 **새로고침해야** 완전히 되돌아간다. 왜 그런지도 생각해보라.)
- **`npm run typecheck`** — 이 문제의 결함은 타입 검사를 전부 통과한다.

## 진행 방식

- 기능을 **하나씩** 말고 **둘씩 묶어서** 밟아본다.
  "필터 → 페이지", "페이지 → 선택", "선택 → 필터", "정렬 → 기본순" 이런 식으로.
- **읽어서 짐작으로 끝내지 말고, 화면과 콘솔에서 직접 재현**한다.
- 고칠 때는 **한 번에 하나만** 고치고, **고친 뒤 확인한 다음** 넘어간다.
- 해설은 먼저 주지 않는다. 리뷰를 먼저 남긴다.

> **시작 힌트.** 3번 페이지로 가서 상태 필터를 `완료`로 바꿔보라.
> 그리고 정렬을 `금액 높은순` → `기본순` 으로 되돌려보라.
