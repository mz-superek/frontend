# 문제 09 — 삭제 확인 다이얼로그 (모달 · 이벤트 · 접근성)

## 상황

문서 목록과 삭제 확인 다이얼로그를 AI에게 시켰다.
받은 결과가 [DocumentManager.tsx](./DocumentManager.tsx)다.

**나는 이 코드를 짠 사람이 아니라 리뷰어다.**
프로덕션에 올려도 되는지 판단하고, 문제가 있으면 *무엇이 / 왜 / 어떻게 고칠지* 설명한다.

버그가 몇 개인지, 있는지 없는지는 알려주지 않는다.

> 모달은 **화면 바깥의 것들을 건드리는** 컴포넌트다. 키보드 이벤트를 문서 전체에서 듣고,
> `body`의 스크롤을 잠그고, 포커스를 옮긴다. 그래서 **뒷정리가 특히 중요**하다.
> 08번에서 `setInterval`에 `clearInterval`을 짝지었던 것과 같은 얘기가 여러 번 나온다.
>
> 그리고 이 화면에는 **되돌릴 수 없는 작업**(삭제)이 있다.
> 확인 다이얼로그가 제 역할을 못 하면 그건 사고다.

## 제품 스펙 (이걸 검증 기준으로 쓴다)

1. **닫기** — `ESC` 키를 누르거나 **바깥의 어두운 영역**을 클릭하면 닫힌다.
   **다이얼로그 안쪽(제목·설명·여백)을 클릭했을 때는 닫히면 안 된다.**
2. **스크롤 잠금** — 열려 있는 동안 뒤쪽 목록이 스크롤되지 않는다.
   그리고 **닫으면 다시 스크롤돼야 한다.**
3. **뒷정리** — 다이얼로그를 **여러 번 열었다 닫아도** 동작이 누적되거나 이상해지지 않는다.
4. **키보드 접근성** — 마우스 없이도 쓸 수 있어야 한다.
   열리면 다이얼로그 안으로 **포커스가 들어가고**, `Tab`으로 이동할 때
   **다이얼로그 밖으로 새어 나가지 않으며**, 닫으면 **원래 누른 버튼으로 포커스가 돌아온다.**
5. **삭제** — 확인을 누르면 **그 문서 하나만** 지워진다.
6. **안정성** — 어떤 조작을 어떤 순서로 하든 렌더링이 깨지면(크래시) 안 된다.

## 검증 도구

- **마우스를 손에서 놓고 해보기** — 스펙 4번은 이 방법 말고 확인할 길이 없다.
  `Tab` 으로 삭제 버튼까지 이동 → `Enter` 로 열기 → `Tab` 을 계속 눌러보기 → `ESC` 로 닫기.
  **지금 어디에 포커스가 있는지** 브라우저가 테두리로 보여준다.
- **여러 번 열었다 닫기** — 스펙 3번. 열고 닫기를 5번쯤 반복한 다음 `ESC` 를 눌러보라.
- **스크롤해보기** — 다이얼로그를 닫은 뒤 목록을 스크롤해본다.
- **콘솔 `[delete]` 로그** — 삭제가 **몇 번** 일어났고 어떤 문서인지 찍힌다.
- **개발자도구 → Elements** — `<body>` 태그의 `style` 속성을 열어두고 다이얼로그를 여닫아 보라.
- **`npm run typecheck`** — 이 문제의 결함은 타입 검사를 전부 통과한다.

## 진행 방식

- 스펙을 **하나씩** 대본다. 특히 **키보드만으로** 한 바퀴 돌아본다.
- **읽어서 짐작으로 끝내지 말고, 화면에서 직접 재현**한다.
- 고칠 때는 **한 번에 하나만** 고치고, **고친 뒤 확인한 다음** 넘어간다.
- 해설은 먼저 주지 않는다. 리뷰를 먼저 남긴다.

> **시작 힌트.** 다이얼로그를 열고 **가운데 흰 영역의 글씨나 여백**을 클릭해보라.
