# 문제 03 — 팀원 초대 폼 (폼 · 유효성 검사)

## 상황

관리자가 새 팀원을 초대하는 폼을 AI에게 시켰다.
받은 결과가 [InviteForm.tsx](./InviteForm.tsx)다.

**나는 이 코드를 짠 사람이 아니라 리뷰어다.**
프로덕션에 올려도 되는지 판단하고, 문제가 있으면 *무엇이 / 왜 / 어떻게 고칠지* 설명한다.

버그가 몇 개인지, 있는지 없는지는 알려주지 않는다.

> 01번은 서버·캐시, 02번은 상태 설계였다. 03번은 **폼**이다.
> 폼은 "사용자가 무엇을 했는가"를 계속 추적해야 해서 상태가 금방 엉킨다.
> 게다가 브라우저에 원래 있던 동작(제출하면 페이지가 넘어간다 같은)과도 부딪힌다.
> **입력 → 검증 → 제출 → 결과**, 이 흐름을 한 단계씩 따라가며 검증한다.

## 제품 스펙 (이걸 검증 기준으로 쓴다)

1. **필수 입력** — 이름과 이메일은 필수다. 비어 있으면 **그 필드마다** 안내가 보인다.
   **둘 다 비어 있으면 둘 다 보여야 한다.** 그리고 채워서 다시 제출하면 채운 필드의 안내는 사라진다.
2. **조건부 필수** — "회사 이메일로 초대"를 켜면 회사 도메인이 필수가 된다.
   **끄면** 그 입력칸도, 그와 관련된 안내도 사라진다.
3. **제출** — 제출해도 **페이지가 새로고침되면 안 된다.** 입력한 값은 그대로 유지돼야 한다.
4. **중복 제출 방지** — 제출이 진행 중일 때는 다시 제출할 수 없다.
   **서버에 같은 초대가 두 번 가면 안 된다.** 진행 중이라는 것도 사용자가 알 수 있어야 한다.
5. **결과 표시** — 성공하면 성공 안내가, 실패하면 **실패 사유**가 보인다.
6. **안정성** — 어떤 조작을 어떤 순서로 하든 렌더링이 깨지면(크래시) 안 된다.

## 검증 도구

- **콘솔 `[api #n]` 로그** — `sendInvite`가 **몇 번** 호출됐는지 그대로 보인다.
  스펙 4번(중복 제출)은 이 로그 말고는 확인할 방법이 없다.
- **콘솔이 통째로 지워지는가** — 제출했는데 로그가 사라지고 입력값도 초기화됐다면
  화면이 **새로고침된 것**이다. 스펙 3번의 신호다.
- **React DevTools (Components 탭)** — `form`과 `errors` state에 지금 뭐가 들었는지 본다.
  화면에 보이는 것과 state가 어긋나는 순간을 잡는 데 쓴다.
  특히 체크박스를 켜고 끌 때 `form.useCompanyDomain`에 **무엇이** 들어가는지 눈으로 확인한다.
- **실패 재현** — `minsu@example.com` 은 이미 팀에 있는 이메일이라 서버가 항상 실패시킨다.
  스펙 5번의 실패 경로를 볼 때 쓴다.
- **`↻ 처음부터 다시` 버튼** — 컴포넌트를 새로 마운트해 초기 상태로 되돌린다.
- **`npm run typecheck`** — 타입 레벨 결함. (이 문제의 결함은 대부분 *런타임*에서 드러난다.)

## 진행 방식

- 스펙을 **하나씩** 코드에 대본다. "이거 지켜지나? 안 지켜지면 어느 줄 때문이고, 어떤 조작으로 재현되나?"
- **읽어서 짐작으로 끝내지 말고, 화면에서 직접 재현**한다.
  재현 순서(어떤 걸 어떤 순서로 눌렀더니 뭐가 어긋났다)까지 말할 수 있어야 진짜 찾은 것이다.
- 고칠 때는 **한 번에 하나만** 고치고, **고친 뒤 화면에서 확인한 다음** 넘어간다.
- 해설은 먼저 주지 않는다. 리뷰를 먼저 남긴다.

> **순서 힌트 하나.** 어떤 결함은 다른 결함에 가려서 안 보인다.
> 화면을 열자마자 제일 크게 걸리는 것부터 치우면 나머지가 드러난다.
