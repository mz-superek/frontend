# 문제 10 — 태그 자동완성 (01·09 복습 종합)

## 상황

문서에 태그를 다는 자동완성 입력을 AI에게 시켰다.
받은 결과가 [TagAutocomplete.tsx](./TagAutocomplete.tsx)다.

**나는 이 코드를 짠 사람이 아니라 리뷰어다.**
프로덕션에 올려도 되는지 판단하고, 문제가 있으면 *무엇이 / 왜 / 어떻게 고칠지* 설명한다.

버그가 몇 개인지, 있는지 없는지는 알려주지 않는다.

> **이번엔 복습이 섞여 있다.** 01번(비동기 경쟁·디바운스)과 09번(이벤트 정리·키보드)에서
> 다룬 것이 다시 나온다. 같은 함정을 **다른 옷을 입혀** 놨으니,
> 그때 배운 걸 스스로 꺼내 쓸 수 있는지 확인해보라.
>
> 자동완성은 실무에서 가장 자주 만드는 UI인데 **제대로 만들기는 까다로운** 컴포넌트다.
> 비동기, 키보드, 포커스, 상태 정리가 한 곳에서 만나기 때문이다.

## 제품 스펙 (이걸 검증 기준으로 쓴다)

1. **후보 표시** — 입력하면 그 검색어에 맞는 후보가 보인다.
   **화면에 보이는 후보는 항상 지금 입력창의 검색어와 맞아야 한다.**
   (늦게 도착한 옛 응답이 최신 결과를 덮어쓰면 안 된다.)
2. **요청 낭비 없음** — 글자 하나 칠 때마다 요청이 나가면 안 된다.
   입력이 멈춘 뒤에 한 번만 나가야 한다.
3. **키보드 조작** — 마우스 없이 쓸 수 있어야 한다.
   `↓`/`↑` 로 후보를 옮겨 다니고, `Enter` 로 고르고, `Esc` 로 닫는다.
   지금 어느 후보가 골라져 있는지 **화면에 보여야** 한다.
4. **선택 후 정리** — 후보를 고르면 태그가 추가되고,
   **입력창이 비워지고, 후보 목록이 닫혀야** 한다.
5. **중복 방지** — 같은 태그를 두 번 넣을 수 없다.
6. **바깥 클릭** — 목록 바깥을 클릭하면 닫힌다.
   여러 번 열고 닫아도 동작이 누적되지 않아야 한다.

## 검증 도구

- **콘솔 `[api #n]` 로그** — 요청이 **몇 번** 나갔고, **어떤 순서로 돌아왔는지** 찍힌다.
  `→` 는 보낸 것, `←` 는 도착한 것이다. **번호 순서가 뒤집히는 순간**을 잡아라.
  (검색어가 짧을수록 느리게 응답하도록 만들어 뒀다.)
- **빠르게 타이핑하기** — `react` 를 최대한 빨리 쳐보고 목록이 뭘 보여주는지 본다.
- **마우스를 손에서 놓기** — 스펙 3번은 이 방법 말고 확인할 길이 없다.
- **같은 태그 두 번 넣어보기** — 콘솔에 경고가 뜨는지 본다.
- **개발자도구 → Elements → Event Listeners** — `document` 에 붙은 리스너 개수를 볼 수 있다.
- **`npm run typecheck`** — 이 문제의 결함은 타입 검사를 전부 통과한다.

## 진행 방식

- 스펙을 **하나씩** 대본다.
- **읽어서 짐작으로 끝내지 말고, 화면과 콘솔에서 직접 재현**한다.
- 고칠 때는 **한 번에 하나만** 고치고, **고친 뒤 확인한 다음** 넘어간다.
- 해설은 먼저 주지 않는다. 리뷰를 먼저 남긴다.

> **시작 힌트.** 콘솔을 열어두고 `react` 를 최대한 빠르게 타이핑해보라.
> 요청이 몇 번 나가고, `←` 가 어떤 순서로 돌아오는지.
