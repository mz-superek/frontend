# 문제 05 — 알림 설정 패널 (`useEffect` 오남용)

## 상황

프로젝트별 알림 설정 화면을 AI에게 시켰다.
받은 결과가 [SettingsPanel.tsx](./SettingsPanel.tsx)다.

**나는 이 코드를 짠 사람이 아니라 리뷰어다.**
프로덕션에 올려도 되는지 판단하고, 문제가 있으면 *무엇이 / 왜 / 어떻게 고칠지* 설명한다.

버그가 몇 개인지, 있는지 없는지는 알려주지 않는다.

> 02번에서 `total`을 `useState` + `useEffect`로 관리하던 걸 계산 한 줄로 바꿨다.
> 05번은 그 이야기의 본편이다. 이 컴포넌트에는 **`useEffect`가 네 개** 있다.
> 각각에 대해 물어야 할 질문은 하나다 — **"이게 정말 `useEffect`여야 하나?"**
>
> `useEffect`는 원래 **바깥 세상과 맞추는** 도구다(타이머, 구독, 브라우저 API 같은 것).
> 화면 안에서 끝나는 일 — 값 계산하기, 버튼 눌렀을 때 할 일 — 에 쓰면
> 한 박자씩 늦고, 렌더가 여러 번 돌고, 낡은 값을 붙들게 된다.

## 제품 스펙 (이걸 검증 기준으로 쓴다)

1. **프로젝트 전환** — 위 탭으로 프로젝트를 바꾸면 그 프로젝트의 **저장된 값이 즉시** 보인다.
   이전 프로젝트 값이 **한 순간이라도** 보이면 안 된다.
2. **변경 감지** — 저장값과 달라지면 `저장 안 됨`, 원래대로 되돌리면 `저장됨`.
   이 표시는 **화면 값과 항상 일치**해야 한다(한 박자 늦으면 안 된다).
3. **경고** — 알림이 켜져 있는데 이메일에 `@`가 없으면 경고가 보인다.
   조건이 풀리면 **즉시** 사라진다.
4. **저장** — `저장`을 누르면 **지금 화면의 값**이 서버에 저장되고,
   저장 직후에는 `저장 안 됨` 표시가 **사라져야** 한다.
5. **렌더 낭비 없음** — 체크박스 한 번, 글자 하나 같은 **한 번의 조작**에
   화면이 여러 번 다시 그려지면 안 된다.
6. **안정성** — 어떤 조작을 어떤 순서로 하든 렌더링이 깨지면(크래시) 안 된다.

## 검증 도구

- **화면 상단 `렌더 N회`** — 이 폼이 몇 번 다시 그려졌는지 센다. 스펙 5번은 이걸로 본다.
  > ⚠️ StrictMode라 숫자가 **2씩** 오를 수 있다. 절대값이 아니라
  > **한 번 조작했을 때 몇 칸 뛰는지**를 보면 된다. 2칸과 6칸은 다른 얘기다.
- **콘솔 `[save #n]` 로그** — 저장이 **몇 번** 일어났고 **어떤 값**이 저장됐는지 그대로 찍힌다.
  스펙 4번은 이 로그와 화면을 같이 봐야 한다.
- **천천히 관찰하기** — 이 문제의 결함 중 몇 개는 **한 순간만** 잘못된 값을 보여주고 곧 맞아진다.
  체크박스를 누르는 순간 화면이 어떻게 변하는지 눈으로 좇아보라.
- **React DevTools (Components 탭)** — `settings`, `dirty`, `warning` state가
  각각 언제 바뀌는지 볼 수 있다.
- **`↻ 처음부터 다시` 버튼** — 렌더 카운트를 0부터 다시 세고 싶을 때.
  (이 문제의 저장값은 메모리에만 있어서 이 버튼으로는 안 돌아간다. 새로고침하면 초기화된다.)
- **`npm run typecheck`** — 이 문제의 결함은 타입 검사를 전부 통과한다.

## 진행 방식

- 스펙을 **하나씩** 대본다. "이거 지켜지나? 안 지켜지면 어느 줄 때문이고, 어떤 조작으로 재현되나?"
- **읽어서 짐작으로 끝내지 말고, 화면과 콘솔에서 직접 재현**한다.
- 고칠 때는 **한 번에 하나만** 고치고, **고친 뒤 확인한 다음** 넘어간다.
- 해설은 먼저 주지 않는다. 리뷰를 먼저 남긴다.

> **시작 힌트.** `저장`을 한 번 눌러보라. 콘솔에 저장은 되는데, 화면에서 뭔가 하나가 안 맞는다.
