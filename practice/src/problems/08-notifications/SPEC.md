# 문제 08 — 알림 피드 (날짜·시간 다루기)

## 상황

알림 목록 화면을 AI에게 시켰다.
받은 결과가 [NotificationFeed.tsx](./NotificationFeed.tsx)다.

**나는 이 코드를 짠 사람이 아니라 리뷰어다.**
프로덕션에 올려도 되는지 판단하고, 문제가 있으면 *무엇이 / 왜 / 어떻게 고칠지* 설명한다.

버그가 몇 개인지, 있는지 없는지는 알려주지 않는다.

> 날짜와 시간은 **틀려도 티가 잘 안 나서** 오래 살아남는 결함이 많다.
> "3분 전"이 "5분 전"이어야 했는지 누가 알겠나. 그래서 **화면에 찍힌 실제 시각과
> 대조해가며** 봐야 한다. 이 화면은 각 알림에 실제 시각도 같이 보여준다.
>
> 그리고 이 문제에는 **05번과 정반대인 지점**이 하나 있다.
> 05번에서는 `useEffect`를 네 개 다 없앴다. 여기엔 **없어서 문제인 곳**이 있다.

## 제품 스펙 (이걸 검증 기준으로 쓴다)

1. **상대 시간** — 각 알림에 `방금` / `N분 전` / `N시간 전` / `N일 전` 이 표시된다.
   화면을 **열어둔 채로 시간이 흐르면 표시도 따라서 갱신**돼야 한다.
   (1분 전에 온 알림이 5분 뒤에도 `1분 전`이면 안 된다.)
2. **미래 시각** — 예약된 알림처럼 **아직 오지 않은 시각**도 목록에 있을 수 있다.
   그런 항목이 `-10분 전` 같은 이상한 표시가 되면 안 된다.
3. **오늘만 보기** — 체크하면 **오늘(자정부터 지금까지) 온 알림만** 남는다.
   어제 온 알림은 몇 시간 전이든 **빠져야** 한다.
4. **보관 만료일** — 화면 아래 만료일은 **고정된 날짜**다.
   화면에서 뭘 조작하든 그 날짜가 바뀌면 안 된다.
5. **안정성** — 어떤 조작을 어떤 순서로 하든 렌더링이 깨지면(크래시) 안 된다.

## 검증 도구

- **각 알림의 실제 시각** — 배지의 상대 시간 옆에 `2026. 8. 7. 오후 3:21` 같은 실제 시각이 찍힌다.
  **둘을 대조**하는 게 이 문제의 기본 검증법이다.
- **지금 시각** — 오른쪽 아래 시계나 `new Date()` 를 콘솔에 쳐서 확인한다.
  "이 알림이 어제 것인가 오늘 것인가"는 **지금이 몇 시인지 알아야** 판단할 수 있다.
- **기다려보기** — 스펙 1번은 **1~2분 가만히 두고 보는 것** 말고는 확인할 방법이 없다.
  화면을 열어두고 다른 일을 하다가 돌아와서 보라.
- **체크박스를 여러 번 토글** — 화면을 다시 그리게 만드는 가장 쉬운 방법이다.
  다시 그릴 때 **바뀌면 안 되는 것이 바뀌는지** 본다.
- **`npm run typecheck`** — 이 문제의 결함은 타입 검사를 전부 통과한다.

## 진행 방식

- 스펙을 **하나씩** 대본다. 특히 **상대 시간과 실제 시각을 나란히** 놓고 본다.
- **읽어서 짐작으로 끝내지 말고, 화면에서 직접 재현**한다.
- 고칠 때는 **한 번에 하나만** 고치고, **고친 뒤 확인한 다음** 넘어간다.
- 해설은 먼저 주지 않는다. 리뷰를 먼저 남긴다.
