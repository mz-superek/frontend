# 문제 07 — 북마크 목록 (커스텀 훅 설계)

## 상황

문서 목록 화면을 AI에게 시켰더니, **"로직을 훅으로 뽑아서 재사용 가능하게 만들었다"** 며 아래를 내놨다.

- [BookmarkLists.tsx](./BookmarkLists.tsx) — 화면
- [useSelection.ts](./useSelection.ts) — 다중 선택 훅
- [useFavorites.ts](./useFavorites.ts) — 즐겨찾기 훅

**나는 이 코드를 짠 사람이 아니라 리뷰어다.**
프로덕션에 올려도 되는지 판단하고, 문제가 있으면 *무엇이 / 왜 / 어떻게 고칠지* 설명한다.

버그가 몇 개인지, 있는지 없는지는 알려주지 않는다.

> 이번엔 **화면 두 개가 같은 훅을 가져다 쓴다.** 거기서 질문이 생긴다.
>
> - 훅을 두 번 부르면 상태는 **각자**인가, **하나**인가?
> - 각자여야 하는 것과 하나여야 하는 것이 섞여 있다면?
>
> 그리고 이 문제에는 **앞서 나온 개념들이 다시 나온다.** 기억하는지 확인해보라.

## 제품 스펙 (이걸 검증 기준으로 쓴다)

1. **선택은 목록마다 따로** — `추천 문서`에서 고른 것과 `내 문서`에서 고른 것은
   서로 **아무 영향이 없어야** 한다. 한쪽에서 고르면 다른 쪽 `N건 선택됨`도 같이 움직이면 안 된다.
2. **즐겨찾기는 하나로** — 즐겨찾기는 사용자 전체의 것이다.
   한쪽 목록에서 추가하면 **두 목록의 `즐겨찾기 N개` 표시가 모두** 같은 수로 맞아야 한다.
3. **즐겨찾기 유지** — 새로고침해도 즐겨찾기가 남아 있어야 한다.
4. **줄 단위 렌더** — 문서 하나를 체크하면 **그 줄만** 다시 그려진다.
   다른 줄의 `렌더` 숫자는 그대로여야 한다.
5. **연속 조작** — 여러 문서를 빠르게 연달아 체크해도 **전부** 반영돼야 한다.
6. **안정성** — 어떤 조작을 어떤 순서로 하든 렌더링이 깨지면(크래시) 안 된다.

## 검증 도구

- **`N건 선택됨` 두 개** — 두 목록의 숫자를 **동시에** 본다. 스펙 1번은 이걸로 잡는다.
- **`즐겨찾기 N개` 두 개** — 마찬가지로 두 숫자를 같이 본다. 스펙 2번.
- **각 줄의 `렌더 N` 배지** — 스펙 4번. (StrictMode라 2씩 오른다. **다른 줄이 같이 오르는지**만 보라.)
- **새로고침** — 스펙 3번. 즐겨찾기를 추가하고 새로고침해본다.
- **개발자도구 → Application → Local Storage** — `practice:favorites` 키에 실제로 뭐가 저장됐는지 볼 수 있다.
  화면과 저장소가 어긋나는 순간을 잡는 데 쓴다.
- **`npm run typecheck`** — 이 문제의 결함은 타입 검사를 전부 통과한다.

## 진행 방식

- 스펙을 **하나씩** 대본다. 특히 **두 목록을 나란히 놓고** 본다.
- **읽어서 짐작으로 끝내지 말고, 화면과 저장소에서 직접 재현**한다.
- 고칠 때는 **한 번에 하나만** 고치고, **고친 뒤 확인한 다음** 넘어간다.
- 해설은 먼저 주지 않는다. 리뷰를 먼저 남긴다.

> **시작 힌트.** `추천 문서`에서 하나만 체크해보라. 그리고 **아래쪽 `내 문서` 영역**을 보라.
