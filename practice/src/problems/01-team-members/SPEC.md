# 문제 01 — 팀 멤버 관리 목록 (TanStack Query v5)

## 상황

관리자 화면에 쓸 "팀 멤버 목록" 컴포넌트를 AI에게 시켰다.
받은 결과가 [TeamMemberList.tsx](./TeamMemberList.tsx)다.

**나는 이 코드를 짠 사람이 아니라 리뷰어다.**
프로덕션에 올려도 되는지 판단하고, 문제가 있으면 *무엇이 / 왜 / 어떻게 고칠지* 설명한다.

버그가 몇 개인지, 있는지 없는지는 알려주지 않는다.

## 제품 스펙 (이걸 검증 기준으로 쓴다)

1. **검색** — 이름 또는 이메일로 검색한다. 검색어를 바꾸면 *그 검색어에 맞는* 목록이 보여야 한다.
2. **페이지 이어붙이기** — "더 보기"를 누르면 *다음* 페이지가 아래에 붙는다. 같은 사람이 두 번 나오면 안 된다.
3. **마지막 페이지** — 더 가져올 게 없으면 "더 보기" 버튼이 사라져야 한다.
4. **역할 변경** — 버튼을 누르면 서버 응답을 기다리지 않고 화면에 즉시 반영된다(낙관적 업데이트).
5. **역할 변경 실패** — 실패하면 ① 값이 원래대로 되돌아가고 ② 사용자가 실패를 알 수 있어야 한다.
6. **안정성** — 어떤 상황에서도 렌더링이 깨지면(크래시) 안 된다.

## 서버(mock)에 대해 알아둘 것

[src/mock/api.ts](../../mock/api.ts)는 서버 역할이라 **고치지 않는다.** 다만 이런 성질이 있다:

- 총 10명, 페이지 크기 4 → 검색어가 없으면 3페이지.
- 응답이 느리고, **검색어가 짧을수록 더 느리다.**
- **`u3`(박지훈)의 역할 변경은 항상 실패한다.** 에러/롤백을 검증하는 고정 케이스.
- 모든 요청이 콘솔에 찍힌다. 요청이 몇 번 갔는지, 어떤 파라미터였는지 확인할 수 있다.

## 검증 도구

- **브라우저 콘솔** — `[api #n]` 로그로 실제 요청을 본다.
- **React Query Devtools** — 우하단 아이콘. 캐시에 어떤 queryKey가 몇 개 있고, 안에 뭐가 들었는지 본다. 이 문제에서 특히 유용하다.
- **새로고침** — 화면에 보이는 값이 *서버의 진실*인지 확인하는 가장 쉬운 방법. 서버 데이터는 `sessionStorage`에 저장돼서 새로고침을 넘겨 살아남는다(탭을 닫으면 초기화).
- **`↻ 처음부터 다시` 버튼** — 서버 데이터 + 캐시 + 컴포넌트를 한꺼번에 초기 상태로 되돌린다. 같은 재현을 여러 번 반복할 때 쓴다.

## 진행 방식 (지난번 피드백 반영)

- 스펙을 **하나씩** 코드에 대본다. "이거 지켜지나? 안 지켜지면 어느 줄 때문이고 어떻게 재현되나?"
- 고칠 때는 **한 번에 하나만** 고치고, 그 하나가 진짜 됐는지 확인한 다음 다음으로 넘어간다.
- 해설은 먼저 주지 않는다. 리뷰를 먼저 남긴다.
