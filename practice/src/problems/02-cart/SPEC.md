# 문제 02 — 장바구니 주문 요약 (순수 React 상태)

## 상황

쇼핑몰 장바구니의 "주문 요약" 컴포넌트를 AI에게 시켰다.
받은 결과가 [Cart.tsx](./Cart.tsx)다.

**나는 이 코드를 짠 사람이 아니라 리뷰어다.**
프로덕션에 올려도 되는지 판단하고, 문제가 있으면 *무엇이 / 왜 / 어떻게 고칠지* 설명한다.

버그가 몇 개인지, 있는지 없는지는 알려주지 않는다.

> 01번은 서버(비동기)가 얽힌 문제였다. 02번엔 **서버가 없다.** 모든 게 화면 안에서
> 동기적으로 벌어지므로, 타이밍 운에 기대지 않고 **같은 조작이면 항상 같은 결과**로
> 재현된다. 대신 "화면에 보이는 값이 지금 상태의 진실을 반영하는가"를 눈으로 따진다.

## 제품 스펙 (이걸 검증 기준으로 쓴다)

1. **수량 조절** — 각 상품의 `+` / `−` 로 수량을 바꾼다. 수량은 **최소 1** 이며 그 아래로는 내려가지 않는다. 바꾸면 화면에 즉시 반영된다.
2. **금액 정확성** — 상품별 소계(가격 × 수량)와 **최종 결제 금액**은 *지금 화면의 수량·할인을 항상* 반영해야 한다. 수량을 바꾸면 결제 금액도 따라 바뀌어야 한다.
3. **쿠폰 할인** — 쿠폰 코드 `SAVE10` 을 적용하면 10% 할인된다. 유효하지 않은 코드면 할인이 없고, **사용자가 입력을 시도한 뒤에** "유효하지 않은 쿠폰" 안내가 보인다(아무것도 안 했는데 처음부터 에러가 떠 있으면 안 된다).
4. **상품 삭제** — 각 줄의 "삭제"를 누르면 **그 상품만** 사라진다. 다른 줄에 표시돼 있던 상태(예: 선물 포장 체크)가 엉뚱한 상품으로 옮겨 붙으면 안 된다.
5. **안정성** — 어떤 조작을 어떤 순서로 하든 렌더링이 깨지면(크래시) 안 된다.

## 검증 도구

- **화면** — 수량·소계·합계·최종 금액을 눈으로 대본다. "지금 수량이 이건데, 결제 금액이 그걸 반영하나?"
- **React DevTools (Components 탭)** — 각 컴포넌트의 `state`(수량 배열, 할인율, `total` 등)에 지금 뭐가 들었는지 본다. 화면에 보이는 값과 실제 state가 어긋나는 순간을 잡는 데 특히 유용하다.
- **`↻ 처음부터 다시` 버튼** — 컴포넌트를 통째로 다시 마운트해 초기 상태로 되돌린다. 같은 재현을 여러 번 반복할 때 쓴다. (이 문제엔 서버가 없어 서버 초기화는 의미 없다 — 재마운트만 쓴다.)
- **`npm run typecheck`** — 타입 레벨 결함. (다만 이 문제의 결함은 대부분 *런타임*에서 드러난다. 타입 검사는 통과할 수 있다.)

## 진행 방식

- 스펙을 **하나씩** 코드에 대본다. "이거 지켜지나? 안 지켜지면 어느 줄 때문이고, 어떤 조작으로 재현되나?"
- **읽어서 짐작으로 끝내지 말고, 화면에서 직접 재현**한다. 재현 순서(어떤 버튼을 어떤 순서로 눌렀더니 뭐가 어긋났다)까지 말할 수 있어야 진짜 찾은 것이다.
- 고칠 때는 **한 번에 하나만** 고치고, 그 하나가 진짜 됐는지 확인한 다음 다음으로 넘어간다.
- 해설은 먼저 주지 않는다. 리뷰를 먼저 남긴다.
